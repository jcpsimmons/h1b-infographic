(**read-only: never write, edit or delete anything under that folder**).

## Data rules (each of these has produced wrong charts before)

- Use `LCA-PERM/data/filing_current/*.parquet`: one row per case, final determination. Use `filing_raw` only for case history.
- **`decision_year` is the calendar year of the decision, not the federal fiscal year.** Never write "FY". Default window for time
  series is **2010 to 2025**: 2007 to 2009 are the old form and a form-transition year, and 2026 is a partial year.
  If you use another window, say why in `meta.caveat`.
- **Program filters.** H-1B applications = `case_kind = 'LCA'` (post-April-2009 form, over 99.9% H-1B). Do **not** use
  `case_kind` alone to find E-3 or H-1B1: those files sit under `LCA-LEGACY` through 2026. Do not filter on `visa_class = 'H-1B'`
  for years before 2011 (it is often blank). PERM = `case_kind LIKE 'PERM%'` (`PERM`, `PERM-NEW`, `PERM-BACKLOG`).
- **Status:** group on `status_n`, never raw `case_status`. Values: `CERTIFIED`, `CERTIFIEDWITHDRAWN` (certified, then the
  employer withdrew), `CERTIFIEDEXPIRED` (a PERM certification that lapsed unused), `WITHDRAWN`, `DENIED`. State exactly which you count as
  "certified" in the caveat. Default: H-1B certified = `CERTIFIED`; PERM certified = `CERTIFIED` plus `CERTIFIEDEXPIRED`.
- **A blank means "not collected", not zero.** Before using any column, count non-null values by year. Known gaps: `wage_from`/`pw`
  are mostly empty in 2015 and 2019 and partly in 2014 and 2018; `secondary_entity`/`secondary_name`/`poc_*` exist only from 2019
  (fully populated from 2020); `employer_fein` only from 2024. Drop or footnote years below about 80% coverage; never plot them as zero.
- **Normalize states** before grouping. Paste `docs/state-map.sql` at the top of your query and join on
  `upper(trim(state)) IN (sm.abbr, sm.name)`. Drop everything that is not a state or DC.
- **Wages:** `wage_from` is in `wage_unit` (Year, Month, Bi-Weekly, Week, Hour) and `pw` is in `pw_unit`. Annualize before comparing:
  Year x1, Month x12, Bi-Weekly x26, Week x52, Hour x2080. Trim implausible values (annual below 15,000 or above 1,000,000) and state
  the trimming in the caveat.
- **Never `SUM(total_workers)` as a workforce number.** It re-attests existing workers. Count applications.
- `employer_key` is a grouping hint, not an identity. To label a group, use its most frequent `employer_name`. Say "employers as named on the filings".
- NAICS codes were revised in 2022; use `naics3` or handle both eras.

## What must never appear

- **No personal information.** No contact names, emails, phone numbers, attorney names, street addresses, or FEINs. Aggregate only.
  (`run-query.mjs` refuses columns with those names.) Individual people are never named. Company names are allowed only as the employer
  named on public filings, in aggregate counts.
- **No accusations.** Presence in this data is not evidence of wrongdoing, and most filings are lawful. Never use words like
  fraud, abuse, scam, illegal, cheating, gaming, exploit, or suggest intent. Write "filed", "applications", "matched", "share of".
  A join between datasets is "an apparent data relationship", never proof.
- **No outside claims.** Do not state anything about laws, caps, policy, or history that you did not compute from the data. The one
  exception is a plain label the data lacks (for example NAICS industry titles): fetch it from the official source page with WebFetch
  (census.gov for NAICS), and cite that URL in `meta.caveat`. Otherwise leave outside context out.
- Keep each JSON under 400 KB and 5,000 rows. Aggregate in SQL.

## Writing the chart

The chart file has three exports. Copy the exemplar and change what differs.

```tsx
export const meta = { id, section, order, title, width, sources, caveat } satisfies ChartMeta;
export function takeaway(rows: Datum[]): string { /* computed from the data */ }
export default function MyChart() { return <Exhibit meta={meta} takeaway={takeaway(rows)}><Plot>...</Plot></Exhibit>; }
```

- Start the file with `"use client";`.
- **`meta.title`**: sentence case, states what is measured, at most 80 characters, no trailing period.
- **`meta.width`**: `"full"` for time series and anything with many labels, `"half"` for a compact chart (a half-width chart shares a row).
- **`meta.order`**: keep the `order` you are given so the section reads in a sensible sequence.
- **`meta.caveat`**: required. One or two plain sentences: what is counted, what "certified" means here, which years or values are
  excluded and why.
- **`takeaway(rows)`**: one or two sentences, 20 to 240 characters, built with template strings from the data so it can never drift
  from the chart. It states what a reader should notice, with at least one specific number. Use `int`, `compact`, `pct`, `usd` from
  `@/lib/format`. Plain language, no hype.
- **Layout and color.** Use `SERIES` colors from `@/lib/theme` in order; red (`SERIES[1]`) is the stamp color, so use it for the one
  thing you want to stand out. Put `<GreenbarGrid />` first inside the chart (the green bands replace gridlines). Use
  `AXIS_TICK`, `CHART_MARGIN`, `<ChartTooltip valueFormat={...} />`. Set `isAnimationActive={false}` on every series.
- **`<Plot>`** wraps the chart and takes exactly one child: the Recharts chart element (`AreaChart`, `BarChart`, `LineChart`,
  `ComposedChart`, `ScatterChart`). Do not pass `width` or `height` to the chart; `Plot` supplies them. Give `Plot` a
  `height` (default 340) that fits the number of rows: about 26 px per row for a horizontal bar chart.
- **Long labels** (employers, occupations): use a horizontal bar chart (`layout="vertical"`, `YAxis type="category"`), give
  the axis `width={190}` or so, and truncate labels to about 28 characters with an ellipsis in code.
- **Custom SVG** is fine for things Recharts does not draw (heat grids, dumbbells): render an `<svg viewBox="..." role="img" aria-label="..." style={{ width: "100%", height: "auto" }}>` directly inside `<Exhibit>` in place of `<Plot>`. Use theme colors, keep text at 12px or larger when rendered, and add a `<title>` on marks for hover text.
- **Maps:** use `<USMap values={{ TX: 123, ... }} format={...} label="..." />` from `@/components/USMap` in place of `<Plot>`;
  it needs postal abbreviations as keys.
- **Direct labels beat legends.** Label lines at their right end, or annotate the one bar that matters. Use `<Legend />` only
  when there are more than two series and direct labels do not fit.
- **Copy:** sentence case, plain words, no all caps, no exclamation marks. Say "applications" for LCAs and "cases" when LCA and
  PERM are combined.
- Do not add libraries, images, fonts, or global CSS.
